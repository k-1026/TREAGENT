## 2. 구조 문제 (발표 전 먼저 고칠 것)

- 장 순서가 수업 규칙과 다름
  - 수업 규칙: 표지 다음 바로 문제, 마지막 장은 요청 한 문장과 MVP URL (Day18 p.8)
  - 현재: 표지(1) → 지난 발표 이후(2) → 스토리보드 이미지 9장(3~11) → 구현·목업·흐름(12~15) → 피치 7장(16~22) → 다음 단계(23)
  - 피치 7장이 전체의 뒤쪽 30%에 있어, 5분 안에 문제·해결을 말할 시간이 없음 (Day18 p.3: 팀당 5분 피치)
- 장 수와 분량
  - 23장 중 스토리보드 이미지가 9장 (`followup.html:97-122`). 요청하신 대로 컨셉을 자세히 말하지 않는 방향과 맞지 않음
  - 피치 7장을 5분에 넣으면 장당 30초 안팎. 구현·목업은 2~3장으로 줄이고, 나머지는 부록으로 빼는 편이 맞음
- 내부 메모가 발표 화면에 그대로 있음
  - 배지: "❌ 미충족", "⚠️ 부분 충족" (followup.html 229, 247, 266 등)
  - 표기: "[확인 필요]", "[결정 필요]", "[기준 통일 필요]", "창작 후보 A/B", "택 1" (followup.html 77, 173, 223, 275, 293, 294, 308, 317)
  - 장: "06 · 다음 단계"의 "결정 필요" 목록 (followup.html 312-323)
  - 이 html은 merge 시 GitHub Pages로 공개됨 (CLAUDE.md "HTML 산출물과 배포 기준"). 발표 판과 내부 점검 판을 나누거나, 발표 판에서 위 표기를 뺀 뒤 올려야 함
