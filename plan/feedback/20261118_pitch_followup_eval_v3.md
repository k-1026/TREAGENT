## 0. 발표자료 구성 규칙

### 줄바꿈
- 한 줄에 들어가는 문장은 같은 줄에 둔다. 두 문장이 한 줄에 들어가면 끊지 않는다.
  - 예: "GPS만으로는 도장이 없습니다. 같은 일이기 때문입니다." (한 줄)
- 두 줄로 나눌 때는 문장이 끝나는 곳에서 끊는다.
  - 예: "GPS로 도착을 확인한 뒤 미션을 마쳐야 방문 인증이 끝납니다.⏎GPS만으로는 도장이 없습니다. 같은 일이기 때문입니다."
  - 예: "MVP는 중구만 안내합니다.⏎중구 밖이면 "지금은 중구만 안내해요"라고 말합니다."
- 한 문장이 한 줄에 들어가지 않으면 조사·쉼표·절이 끝나는 곳에서 끊는다. 예: "장부에 앨범을 더하고, ⏎주머니는 홈에서 따로 엽니다."
- 단어 중간에서 끊지 않는다 (`word-break: keep-all`).
- 한 칸에 세 줄 이상 나오지 않게 한다. 세 줄이 되면 문장을 줄이거나 칸을 나눈다.
- 줄 길이는 비슷하게 맞춘다. 한 줄만 짧고 다음 줄이 길어지지 않게 한다.

### 제목과 목록
- 소제목: 한 줄, 명사형, 15자 안팎. 문장형(~합니다, ~있습니다)은 쓰지 않는다.
- 항목 목록이 사람 이름 옆에 붙을 때는 항목마다 한 줄씩 쓰고, 항목 앞에는 🤖 이모지를 붙인다 (팀 페이지 규칙).

### 강조와 표기
- 밑줄 강조는 쓰지 않는다. 괄호도 밑줄 없이 쓴다.
- 발표 판에는 배지(❌·⚠️), `[결정 필요]`, 후보 A/B 목록, "기준 통일 필요"를 넣지 않는다. 확인 전 사실만 `[확인 필요]`·`[미검증]`으로 짧게 표시한다.
- 확인 안 된 일정(예: "[확인 필요: 일정]")은 발표 판에 넣지 않고 이 문서에 남긴다.

### 내용
- 장 구조: 표지 다음 바로 문제. 마지막 장은 요청 한 문장 (수업 p.8). 장마다 메시지 한 줄, 숫자 하나, 출처 한 줄 (p.9).
- 같은 내용을 두 장에 쓰지 않는다. 한 장에서 설명하고, 다른 장에서는 한 줄로 참조하거나 뺀다.
- 목업: 화면만 보이고, 휴대폰은 비율(390:844)대로 꽉 찬다. 조작 드롭다운은 휴대폰 옆 패널에 둔다.
- 외부 링크와 버튼은 넣지 않는다 (사용자 결정, 2026-11-18).
- 금칙어 "유일·최초·최고"는 쓰지 않는다 (CLAUDE.md).
- 공개 전 확인: html은 `main` 병합 시 GitHub Pages로 공개된다. 팀원 이름은 본인 확인 후 올린다.

- 원문: 매일신문 「[극한 폭염] "밤에도 펄펄 끓는데" 대구 무더위쉼터 20%만 오후 6시 이후 운영」, 2026-08-04 (https://www.imaeil.com/page/view/2026080416070128215). 원문 본문 확인.
- 확인된 문장 (원문 그대로):
  - 운영 중인 무더위쉼터는 모두 1천196곳
  - 오후 6시 이후까지 운영하는 시설은 235곳(19.6%)
  - 24시간 운영하는 쉼터는 5곳 (삼덕119안전센터, 서문로119안전센터, 대신119안전센터, 남산119안전센터, 수성구청 등)
  - 오후 6시에 운영을 종료하는 시설은 609곳 (전체의 절반 정도)
- 확인 결과: 발표의 1,196 / 235 / 19.6% / 5곳은 원문과 일치. 헤드라인의 "20%"는 19.6%의 반올림이다.
- 주의: 원문의 3개 구간 합 (609 + 235 + 195 = 1,039)이 1,196과 맞지 않는다. 157곳의 운영 시간 구분은 원문에 없다. 발표에서 "오후 6시 이후 운영 235곳"만 말하고, 609곳은 말하지 않는다.
- 기준 시각: 원문은 "오후 6시 이후 운영 여부"로 센다. 발표 문장도 이 기준을 쓴다.
- 폭염특보 연장 운영 (원문): 실제 연장 운영 32곳, 주말 추가 운영 46곳. 발표에 쓰면 원문 인용으로 표기.
- 여전히 확인 안 됨: 대구시 공식 자료 (원문은 "현황 자료를 전수 분석한 결과"라고만 함). 발표 전 대구시 공식 자료 확인을 권장 `[확인 필요]`.
