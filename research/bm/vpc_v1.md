# 가치 제안 캔버스 v1: 사용자(혼행객)와 지불자(대행사·지자체)

- 작성일: 2026-11-24
- 상태: 초안. 팀 확인 전이고, 레드팀 검증의 대상입니다 ([redteam_log_v1.md](redteam_log_v1.md)).
- 방법: 고객 쪽(일·불편·기대)은 **고객 근거**(VOC, 고객 전략)에서만 채우고, 제공 쪽(제품·불편 해소·기대 창출)은 우리 설계에서 채워 짝을 맞춥니다. 고객 쪽을 우리 기능에서 거꾸로 채우지 않습니다 (강의 흔한 오류).
- 구조 출처: Strategyzer, The Value Proposition Canvas (Day13 강의 자료 p.15). 칸 이름의 한국어 표기는 강의 정리를 따랐습니다.
- 구현 상태 표기: **구현**(코드에 있음) / **일부** / **설계**(문서에만 있음) / **없음**
- 짝 없음은 빼거나 근거를 찾아야 합니다. 이 문서에서는 이유를 적었습니다.

## 1. 사용자: 1박 2일 대구 혼행객

### 1-1. 고객 쪽 (고객의 사실)

| 칸 | 내용 | 근거 |
|---|---|---|
| **일 (Jobs)** | 귀가 일정 사이 여유 시간에 중구에서 짧게 대구다운 장소를 둘러본다. 지금 갈 수 있는 다음 장소를 확인하고 길을 찾아 이동한다 | 고객 전략 4장 상황 가설 (**가설**, 혼행객에게 반복되는지는 인터뷰 필요). 강의의 `ax/jtbd.md`는 저장소에 없음 |
| **불편 1 (Pains)** 운영 정보가 현장과 다름 | 방문 직전 확인한 운영 정보와 현장이 달라 헛걸음하거나 일정을 다시 짬 | VOC 휴관·공사·운영 변경 **10건**, 알아보기 단계 8건, 강도 3은 3건 (id 7·8·9) |
| **불편 2** 기다림과 혼잡 | 포토존·기구·먹거리·좌석을 위해 1시간 안팎 기다리거나 서서 먹음 | VOC 대기·혼잡 **13건** (축제 글 포함, 과대 가능) |
| **불편 3** 날씨 | 덥고 습하거나 바람·냉기 때문에 오래 머물기 어려움 | VOC 날씨·온도 **4건** (id 22, 32, 36, 45) |
| **기대 (Gains)** | 지금 갈 수 있는 다음 장소와 도착 후 할 일이 분명하다. 앱을 닫거나 장소가 바뀌어도 기록이 유지된다 | 고객 전략 4장 성공 기준 (가설). VOC에는 "기대"를 직접 말한 글이 없고 요청 4건(id 16, 19, 47, 52)은 먹거리·좌석·시설·콘텐츠 관련임 |

### 1-3. 짝 맞추기 (정합성 점검)

| 점검 | 결과 | 이유 |
|---|---|---|
| 고객 쪽 세 칸이 모두 파일 근거로 채워졌는가 | **아니오** | 일(Jobs)과 기대(Gains)는 고객 전략의 **가설**이고, 인터뷰 근거가 없음. 불편(Pains)만 VOC 근거 있음 |
| 불편 Top 3마다 짝이 되는 불편 해소가 있는가 | **아니오 (2/3)** | 불편 2(혼잡)에 짝이 없음. 불편 1은 **일부**, 불편 3은 구현이지만 새 위험이 있음 |
| 짝이 없는 제공 항목(기능)이 있는가 | 있음 | 장부·앨범·주머니는 어느 고객 쪽 칸과도 짝이 없음. 스토리보드의 수집 요소이고, VOC에서 재방문 근거가 0건임 (고객 전략 2장). 빼거나 근거를 찾아야 함 |
| 가장 큰 불편에 가치 제안 문장이 직접 답하는가 | **일부** | 가장 점수가 높은 불편은 혼잡(21)이지만 가치 제안은 휴관·운영 변경(20)에 답함. 첫 파일럿 선택 이유는 "운영자가 상태를 바꿀 수 있어 효과를 확인하기 쉽다"임 (고객 전략 2장) |
| BM 캔버스 2블록 문장이 이 점검 뒤에도 그대로인가 | 수정 필요 | 가치 제안에 "혼잡"을 넣지 않고, "휴관·운영 변경과 날씨"로 범위를 좁혀야 함 → [bm_canvas_v1.md](bm_canvas_v1.md) 2블록 |

## 2. 지불자: 행사 대행사 PM과 지자체 담당자

### 2-1. 고객 쪽

| 칸 | 내용 | 근거 |
|---|---|---|
| **일 (Jobs)** | 여러 장소 담당자와 일정을 맞추고, 당일 변경과 참가자 문의에 대응하고, 종료 후 발주처에 결과를 보고한다 | 고객 전략 4장 (**가설, 인터뷰 전**) |
| **불편 1** 변경 공지 | 거점이 바뀔 때 공지 채널을 다시 돌려야 함 | 고객 전략 2장: "있는지 검증" 단계. **미측정** |
| **불편 2** 결과 취합·보고 | 행사 후 참여 기록을 모아 발주처에 보고함 | 고객 전략 2장: **미측정** |
| **불편 3** 지자체 쪽 | 예산·성과 승인 때 지역 방문·행사 성과에 대한 산출물이 필요함 | 고객 전략 4장 (가설) |
| **기대 (Gains)** | 거점 변경을 한 번 입력해 참가자에게 알리고, 거점별 시작·인증·완주를 집계해 보고한다 | 고객 전략 4장 성공 기준 (가설) |

### 2-2. 제공 쪽

| 칸 | 내용 | 구현 |
|---|---|---|
| **제품·서비스** | 코스 제작·운영 용역, 운영자 웹, 거점별 집계 리포트 | 운영자 웹 **없음**, 방문 기록 **없음**. 코스 제작은 사람이 하는 서비스 |
| **불편 해소 1** (변경 공지) | 운영자가 상태를 바꾸면 참가자 앱이 다음 재평가 때 반영 (즉시 알림은 P1) | **없음** (운영자 화면 없음, 재평가는 이탈 감지만 있음) |
| **불편 해소 2** (보고) | 거점별 시작·인증·완주 집계 | **없음** |
| **기대 창출** | 한 번 입력 → 안내 반영, 집계 리포트 | **없음** |

### 2-3. 짝 맞추기

| 점검 | 결과 | 이유 |
|---|---|---|
| 고객 쪽 세 칸이 파일 근거로 채워졌는가 | **아니오** | 전부 가설이고 미측정. 인터뷰가 필요 |
| 불편 Top 3마다 짝이 있는가 | 짝은 설계상 있음 | 그러나 **전부 미구현** |
| 짝이 없는 제공 항목이 있는가 | 코스 제작 용역 | 고객 쪽에 "제작을 맡기고 싶다"는 불편·기대 근거가 없음. 구매 이유는 인터뷰로 확인해야 함 |
| 가장 큰 불편에 가치 제안 문장이 답하는가 | 확인 불가 | 가장 큰 불편이 무엇인지 모름 (미측정) |

## 3. 요약: 이 캔버스가 말해 주는 것

- **사용자 쪽은 불편 근거가 있고(VOC 52건), 지불자 쪽은 근거가 없습니다.** 돈을 내는 쪽의 불편이 가설입니다.
- 사용자의 불편 3개 중 해소가 있는 것은 날씨(구현), 운영 정보(일부)이고, 혼잡은 짝이 없습니다.
- 지불자에게 약속한 가치(운영자 웹, 집계, 변경 공지)는 **모두 아직 없습니다.**
- 짝 없는 제공 항목: 장부·앨범·주머니(고객 근거 없음), 코스 제작 용역(구매 이유 근거 없음).
