# 게임 스토리보드 v1 (대구 히든 퀘스트)

> **주의 (2026-11-13)**: 퀘스트·단서·미션·체력·팀 모드·사과 스탬프는 구컨셉. 현재는 길(코스)·장부·능금 스탬프이며 게임 요소는 최소. 현재 기준은 [brand/game_concept.md](../brand/game_concept.md), [plan/daeprica_hidden_quest_plan.md](../plan/daeprica_hidden_quest_plan.md).

- 작성일: 2026-11-10
- 목적: 퀘스트 생성·작동 흐름과 하랑이 행동·대사 구조를 장면 단위로 정리. 구현과 에이전트 설계의 기준 문서.
- 주의: 이 문서는 게임용입니다. 영상용 훅·전환은 `storyboard/hooks_v2_diverse.md`, `storyboard/transitions_v2.md`를 봅니다.
- 표기: 규칙과 수치는 **창작 초안**. 팀 결정 전입니다. 근거가 있는 내용만 근거 파일을 붙입니다.

## A. 퀘스트 생성과 작동 흐름 (시스템 스토리보드)

### A-1. 전체 흐름 (한 장 요약)

```
[입력]                    [규칙 검사]              [생성]                 [검수·게시]           [플레이]              [기록·다음 날]
날씨 (기온·체감·강수)  ─┐
장소 정보 (실내/야외,  ─┼─► R1 폭염 잠금   ─┐
  운영 여부, 혼잡)      │   R2 운영 확인    ├─► 퀘스트 후보 ─► 에이전트: 단서·대사 ─► 사실 검수 ─► 운영자 승인 ─► 오늘의 퀘스트 ─► 이동·미션 ─► 스탬프·도감 ─► 다음 날 재생성
플레이어 상태 (체력,  ─┘   R3 혼잡 분산 ─┘                                                                              (체력 0 → 쉼터 안내)
  팀 인원, 최근 쉼터)
```

### A-2. 장면별 설명

| 장면 | 무엇이 일어나나 | 누가 결정하나 | 근거 |
|---|---|---|---|
| 1. 입력 수집 | 날씨, 장소 운영 상태, 플레이어 상태를 받음 | 시스템 (데이터 연동) | 기온 예보 자료 (YTN 2026.7.13) |
| 2. 규칙 검사 | R1 체감이 기준 이상이면 야외 잠금, R2 휴관·영업 종료 장소 제외, R3 대기가 긴 장소는 뒤 순서 | 규칙 엔진 (사람이 정한 규칙) | `research/painpoint/voc_classified.csv` (대기 13건, 운영 변경 10건) |
| 3. 퀘스트 후보 생성 | 규칙을 통과한 장소로 후보를 만듦 | 규칙 엔진 | — |
| 4. 문장 생성 | 에이전트가 단서 문장과 하랑이 대사를 만듦 | AI 에이전트 (문장만 담당) | — |
| 5. 사실 검수 | 역사·장소 설명을 근거 자료와 대조. 틀리면 반려 | 검수 규칙 + 운영자 | `research/daegu_history_tour_cases.md` 3-3 (AI 투어 역사 설명 부정확 지적) |
| 6. 운영자 승인 | 오늘의 퀘스트 목록을 확인하고 게시 | 운영자 | — |
| 7. 플레이 | 장소를 이동해 미션 수행. 체력이 줄고 쉼터에서 회복 | 플레이어 | — |
| 8. 기록 | 스탬프, 도감, 방문 장소 기록, 쉼터 체크인 저장 | 시스템 | — |
| 9. 다음 날 재생성 | 날씨가 바뀌면 같은 장소도 다른 퀘스트로 나옴 | 시스템 | — |

### A-3. 예외 장면 (반드시 그릴 것)

| 예외 | 시스템 반응 | 플레이어에게 보이는 것 |
|---|---|---|
| 체감이 기준 이상 | R1: 야외 퀘스트 잠금, 실내·그늘 퀘스트 개방 | "오늘은 실내 퀘스트가 열렸어요" (하랑이 놀람 표정) |
| 장소가 휴관 | R2: 후보에서 자동 제외, 대체 장소 제시 | 대체 장소 카드 |
| 대기가 긴 장소 | R3: 순서를 뒤로 미룸 | 이른 시간·늦은 시간 추천 문구 |
| 체력 0 | 야외 퀘스트 중단, 가까운 쉼터 안내 | 하랑이 차분 표정 + 쉼터 경로 |
| 검수에서 설명 오류 | 게시 중단, 운영자에게 반려 | 플레이어에게는 보이지 않음 |
| 팀 모드에서 한 명 쉼 | 쉬는 사람은 쉼터, 나머지는 탐색 계속 | 팀 상태 표시 |

### A-4. 에이전트 역할 한정

- 에이전트가 하는 일: 단서 문장과 대사 **문장 생성**
- 에이전트가 하지 않는 일: 퀘스트 열림·잠금 결정, 표정 결정, 운영 여부 판단 (규칙 엔진이 함)
- 검수: 사실과 말투 검사 후 운영자 승인

## B. 하랑이 행동과 대사 구조 (캐릭터 스토리보드)

### B-1. 트리거 표

| 트리거 | 발생 조건 | 표정 | 대사 방향 |
|---|---|---|---|
| 퀘스트 완료 | 미션 완료 | 행복 | 칭찬과 다음 안내 |
| 쉼터 안내 | 체력 낮음 또는 0 | 차분 | 쉬어 가자는 안내 |
| 새 퀘스트 열림 | 날씨 변화로 퀘스트 해금 | 놀람 | 새 길을 알림 |
| 단서 발견 | 장소에서 단서 획득 | 차분 또는 행복 | 단서 설명 한 줄 |
| 기본 | 그 밖의 상태 | 평상 | 짧은 인사 |

### B-2. 표정 결정 규칙

```
이벤트 발생 → 트리거 표에서 표정 선택 (규칙, AI 아님)
  └─ 우선순위: 체력 0 > 퀘스트 완료 > 새 퀘스트 > 단서 발견 > 기본
```

### B-3. 대사 생성 구조

```
트리거 + 장소 정보 + 말투 규칙 (짧고 따뜻하게, 한 문장 두 줄 이내)
  → 에이전트가 대사 후보 생성
  → 사실 검수 (장소 설명과 대조)
  → 대사창 출력
```

- 말투 규칙 예: 존댓말, 짧은 문장, 과장 금지, 근거 없는 역사 금지
- 금칙어: 본문과 대사에 쓰지 않음 (유일, 최초, 최고 등 후보는 팀 확정 전까지 보수적으로 피함)

### B-4. 장면 카드 (예시 3장)

| 장면 | 화면 | 하랑이 표정 | 대사창 문구 (예시) | 트리거 |
|---|---|---|---|---|
| 1 | 폭염 아침, 퀘스트 목록 열림 | 놀람 | "오늘은 실내 길이 열렸어요!" | 새 퀘스트 열림 |
| 2 | 쉼터 도착, 체력 회복 | 차분 | "여기서 잠깐 쉬어 가요." | 쉼터 도착 |
| 3 | 미션 완료, 사과 스탬프 획득 | 행복 | "단서 세 개를 다 모았어요!" | 퀘스트 완료 |

- 대사는 예시입니다. 실제 문장은 팀이 말투를 정한 뒤 확정합니다.

## 프롬프트 정리

### P-1. 흐름도 그리기 (A-1 시각화용)

> 아래 단계를 가로 흐름도로 그려 줘. 상자는 둥근 모서리, 화살표는 실선. 상단에 입력 3개(날씨, 장소 정보, 플레이어 상태), 가운데 규칙 검사 3개(R1 폭염 잠금, R2 운영 확인, R3 혼잡 분산), 오른쪽에 생성→검수→승인→플레이→기록→다음 날 재생성 순서로 연결. 색은 도트 RPG 느낌의 따뜻한 팔레트(빨강, 민트, 노랑, 크림), 글자는 한국어 고딕체. 배경은 크림색 단색.

### P-2. 장면 카드 일러스트 (B-4용)

> Pixel-art RPG style scene, chibi squirrel mascot named Haring (apple-red fur, cream face and belly, green leaf on the head, fan in hand, small bag). Scene: [장면 설명]. Expression: [행복 / 차분 / 놀람]. Warm Daegu summer street, pixel art, clean outlines, plain background for a dialogue box at the bottom. No text in the image. (이름은 가칭이므로 이미지 안에 글자를 넣지 않음)

- 장면 설명 예: "a shaded alley with a cooling shelter sign, Haring sitting under a tree"
- 표정 예: "surprised open mouth" (놀람), "calm gentle smile" (차분), "happy closed eyes with open mouth" (행복)

### P-3. 대사창 화면 목업 (B-4용)

> Pixel-art RPG dialogue box UI, navy box with white border at the bottom of the screen, name tag above the text, gold name label, Korean text inside, small expression portrait of Haring on the left. Clean flat style. Background: a Daegu street at noon, pixel art.

### P-4. 에이전트 프롬프트 초안 (A-4 구현 참고용, 문장 생성만 담당)

> 역할: 대구 히든 퀘스트의 단서 문장과 하랑이 대사를 만든다. 규칙을 바꾸지 않는다.
> 입력: 트리거(예: 퀘스트 완료), 장소 이름, 장소 설명(근거 문장), 말투 규칙.
> 출력: 대사 2개 후보, 각 한 문장 두 줄 이내. 근거 문장에 없는 역사·사실은 쓰지 않는다. 금칙어(유일, 최초, 최고, 가장, 최대)를 쓰지 않는다.
> 표정은 정하지 않는다. 표정은 트리거 표가 정한다.

### P-5. 스토리보드 검수 체크 (팀 검토용)

> 이 흐름도에서 (1) 규칙 엔진과 에이전트의 역할이 섞인 부분이 있는지, (2) 예외 장면이 빠진 곳이 있는지, (3) 표정 결정 규칙이 우선순위 없이 중복되는지 점검해 줘.
