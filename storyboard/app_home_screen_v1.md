## 2. 배치 (세로 9:16, 창작, 2026-11-17 수정)

```
┌─────────────────────────┐
│ 상태 영역 56px             │
│ [날씨 배지 ▾] 구·군·기준 시각  │  ← 장면 위 좌상단(상태 영역 바로 아래), 탭하면 지역 변경
│ ┌─────────────────────┐ │
│ │ 도트 방 장면 (3:2 그림)  │ │  ← 높이 316 (상태 영역 56 + 그림 260)
│ │ 말풍선 / 하랑이 (앱에서 얹음)│ │
│ │ [배너: 특보·경로 변경]    │ │  ← 해당 상태에만, 장면 아래쪽에 겹침
│ └─────────────────────┘ │
│ [주 버튼 슬롯] 고정 높이     │  ← 상태에 따라 내용만 바뀜
│ [코스 전체|오늘의 길][쉼터][주머니] │  ← 퀵 버튼 3개 고정
│ 오늘의 추천 길 (세로 카드 1~3개) │  ← 옆으로 밀지 않음
│ (자리가 남으면 도장 미리보기)   │
│ ─────────────────────── │
│   홈   ·   장부   ·  내 정보  │
└─────────────────────────┘
```

- **상태가 바뀌어도 주 버튼과 추천 길의 위치는 같습니다.** 이어하기 카드를 따로 쌓으면 아래가 전부 밀려 내려오기 때문입니다.
  - 주 버튼 슬롯: 진행 없음 = 오늘의 길 확인, 진행 있음 = 이어하기, 폭염·호우·날씨 확인 불가 = 가까운 쉼터 보기.
  - 진행 중에는 퀵 버튼 첫 칸이 "오늘의 길"이 됩니다. 진행 중 새 길을 고르면 경고창을 띄운 뒤에만 새로 시작합니다 (D-08 결정).
- **MVP는 중구 코스 1개(C01)이고, 오늘의 모드에 따라 경로가 둘(탐험/실내) 중 하나로 정해집니다.** 코스가 늘어도 홈에는 1~3개만 세로로 쌓습니다.
- **추천 길은 세로로 쌓고 옆으로 밀지 않습니다.** P0에서는 규칙 엔진이 모드를 정하고 검수된 DB에서 경로를 고르며(AI가 코스를 만들지 않음), 하루 추천 길은 1~3개 `[예시]`라 밀어서 볼 만큼 많지 않습니다 (plan/spec/treagent_tech_spec_v1.md:484, brand/game_concept.md:35). 전체 코스는 "코스 전체"에서 봅니다.
- 하단 탭 장부(S-09), 내 정보(S-10) 화면도 목업에서 눌러 볼 수 있습니다.


- 장면 영역: 폭 390 x 높이 316 (상태 영역 56 + 그림 260, 3:2 그림을 폭에 맞춤). 논리 화면 390 x 844 기준 `[확인 필요: 실제 기기 폭과 안전 영역]`. 배지와 말풍선이 겹치지 않게 배지는 좌상단, 말풍선은 문과 창 사이 벽에 둡니다.
- 앱이 얹는 것: 날씨 배지, 하랑이 스프라이트, 말풍선. 그래서 그림에는 하랑이를 넣지 않고 자리를 비웁니다.
  - 왜 굳이: 표정·대사에 따라 하랑이를 바꿔 끼우려면 배경과 분리돼 있어야 합니다.
  - 없으면 깨지는 것: 배경 이미지를 표정 수만큼 다시 만들어야 합니다.
- 장면 안 자리: 왼쪽 위 비움(날씨 배지), 가운데 아래 바닥 비움(하랑이), 하랑이 머리 위 비움(말풍선).
- **말풍선 꼬리**: 말풍선의 아래 가장자리를 하랑이 머리 위에 고정하고 꼬리가 하랑이 머리를 향하게 합니다. 대사가 길어지면 위로 자랍니다 (날씨 배지와 겹치지 않는 한도는 대사 길이 상한으로 정함 `[결정 필요]`).
- **방 안에서 눌러지는 사물 (보조 진입)**: 책상 위 장부 그림 = **오늘 페이지**, 창 = 날씨 상세(기준 시각, AWS 여부), 하랑이 = 대사 넘기기. 책에는 "오늘 페이지 ▾" 표시를 붙여 알아보게 합니다.
  - 왜 굳이: 방 그림이 곧 메뉴가 되면 컨셉이 살아납니다. 홈은 "펼친 장부의 오늘 페이지"로 표현하는 안입니다 (storyboard/game_flow_story_v1.md 6절).
  - 없으면 깨지는 것: 방이 장식으로만 남습니다.
  - 주의: 그림만으로는 눌러지는지 알기 어려워서 하단 탭과 버튼을 대체하지 않고 보조 진입으로만 둡니다. 첫 실행 안내가 필요한지는 `[확인 필요]`.
- **장부 두 진입의 역할 구분 (2026-11-17 수정)** (창작 후보 2개):
  - 후보 A (목업 반영, 추천): **하단 장부 탭 = 장부 전체**(책갈피 [칸] [내 여행] [앨범]), **책상 위 장부 그림 = 오늘 페이지**(오늘 걸을 장소 3곳의 칸과 내 도장 여부, 길 확인으로 연결. 길동무 수는 보이지 않음). 기록 보관소와 오늘 할 일이 나뉩니다.
  - 후보 B: 책 그림 = 가장 최근 "내 여행 한 장" 바로 열기. 오늘 페이지가 사라지고 홈이 기록 쪽으로 기웁니다.
  - **길동무 수는 장소(칸) 단위로만 보여 줍니다 `[사용자 결정 2026-11-17]`.** "이 칸에는 앞서 길동무 [N]명이 들렀어요", 0이면 "아직 아무도 안 걸은 칸이에요!"를 장소 방문 때 띄웁니다. 코스 단위로 합산하지 않습니다. 코스는 날씨·시간대에 따라 매번 다르게 짜여 집계의 단위가 될 수 없기 때문입니다 (코스를 AI가 짜는지, 규칙 엔진이 검수 DB에서 고르는지는 명세 F-19 기준 규칙 엔진이라 `[확인 필요]`). 그래서 오늘 페이지 위쪽 문구는 "비어 있는 칸 N곳 + 길동무 N명"을 한 문장으로 쓰지 않습니다. **길동무 수가 보이는 때** `[사용자 결정 2026-11-17]`: 장소에 도착해 장소 상세를 볼 때(인증 전, 본인 미포함)와 미션 인증을 끝낸 직후(본인을 더한 수로 갱신, 같은 칸 중복 없음), 그리고 장부 [칸]입니다. **오늘 페이지에는 길동무 수를 보이지 않습니다** `[사용자 결정 2026-11-17]`.
  - 목록 항목은 이름과 설명 사이를 한 줄 띄웁니다 (주머니, 장부 목록, 오늘 페이지).
  - 앨범을 홈에서 따로 들어가게 하는 안은 쓰지 않습니다 (game_flow_story_v1.md 9-2절 결정).
- **장부의 구성 `[확정]`** (brand/worldview.md 5-1절, storyboard/game_flow_story_v1.md 9-2절): 책갈피 [칸] [내 여행] [앨범] 세 개. 이전 목업의 "지난 여행/도장/주머니"는 이 구성에 맞춰 고쳤습니다.
  - [칸]: 공동 장부의 칸(스팟의 날씨·시간대·요일 조합), 앞서 들른 길동무 수, 내가 채운 칸의 도장과 날짜. **도장 모음 화면은 따로 두지 않고 "내가 채운 칸만 보기"로 대신합니다.** 권역별 달성률은 권역 완주(game_concept.md 7절, F-17)의 자리를 이 책갈피 위쪽에 둡니다 (P2, 권역 구분과 완주 조건은 `[예시]`).
  - [내 여행]: 여행 1회가 한 장. 날짜, 장소, 도장, 하랑이의 한 줄. 본인 것만 봅니다 (F-11).
  - [앨범]: 해금한 고정 컷씬만 보입니다. 안내 정보는 없습니다.
  - **주머니는 장부 안이 아니라 홈의 [주머니] 버튼으로 들어갑니다.** 열쇠, 손수건, 배지, 인증서가 담깁니다 (아이콘 4종, 배지와 인증서는 잠정·P2) (game_flow_story_v1.md 9-2절). 이전 퀵 버튼 "지난 여행"은 [내 여행] 책갈피와 겹쳐 "주머니"로 바꿨습니다.
- **능금 도장 `[사용자 결정 2026-11-17]`**: 한 코스에는 장소가 3곳이고, 각 장소를 방문해 미션을 마칠 때마다 도장을 1개 받아 **한 코스의 도장은 총 3개**입니다. 도장은 스팟이 찍어 주는 방문 증거이고 하랑이가 찍지 않습니다 (game_flow_story_v1.md 8절). **도장을 받는 시점은 미션 완료 화면(S-18)이고, 방문 인증과 같은 일입니다 `[사용자 결정 2026-11-17]`.** 인증 방식은 **GPS + 미션**입니다. GPS로 도착을 확인하고(S-06), 미션을 마치면(S-15~S-17) 인증이 끝나 도장이 찍힙니다(S-18). 미션 없이 GPS만으로는 도장이 찍히지 않습니다. 명세 F-10의 "인증할 때마다"와 D-05의 B안(GPS+현장 단서)이 이 결정에 해당합니다.
  - **코스의 장소 수 `[사용자 결정 2026-11-17, 회의 후 통일]`**: 모든 코스는 장소 3곳입니다. 서버 시드가 이미 3곳입니다 (dev/supabase/migrations/seed_courses.sql): 코스 C01 "중구 근대골목 걷기", 탐험 경로 = 동성로 → 대구 근대골목 → 대구약령시한의약박물관, 실내 경로 = 대구약령시한의약박물관 → 대구향토역사관 → 국채보상운동기념관(민감 역사 `caution`). 기존 코스 A의 서문시장은 빠졌고 3호선 코스는 시드에 없습니다. 제목은 후보 A(후보 B: 중구 약령시 한 바퀴), 소요 60분은 임시입니다 `[확인 필요]`.
  - **미션은 코스가 아니라 장소마다 종류가 다릅니다 `[사용자 결정 2026-11-17]`.** 동성로와 근대골목처럼 한 구간 안에도 식당, 박물관 등 장소가 여럿이라서, 영수증형/퀴즈형 같은 미션 종류는 **장소별**로 정합니다. 장소 목록은 조사 중이고, 정해지면 DB 입력 때 미션 종류를 함께 넣습니다. 그래서 코스의 "3곳"이 구간(동성로, 근대골목 등)인지 미션을 하는 장소 3개인지는 장소 목록이 정해진 뒤 확정합니다 `[확인 필요]`.
  - **MVP 범위 `[사용자 결정 2026-11-17]`**: 지금 MVP는 **중구만** 구현합니다. 구·군 선택은 중구로 고정하고, 위치가 중구 밖이면 "지금은 중구만 안내해요" 상태를 보여 줍니다. 권역 구분과 완주 조건, 권역별 달성률은 추후 논의라 MVP에서 제외합니다 (P2).
- **장부에는 지도가 없습니다.** 지도는 S-05 여행 지도에서만 나옵니다. 지난 여행의 경로를 지도로 다시 보여 줄지는 정해지지 않았습니다 `[결정 필요]` (스팟 위치는 장소 DB 값이라 쓸 수 있고, 이용자 좌표는 저장하지 않는 원칙은 유지: brand/game_concept.md 185행).

## 3. 요소 목록

**필수**
1. 날씨 배지: 기온, 체감, 기준 시각. AWS 여부는 탭하면 보이는 상세에 둡니다 `[확인 필요]` (CLAUDE.md 폭염·한파 안전 정보 기준).
2. 도트 하랑이와 말풍선: 호칭은 이름이고, 없으면 "길동무". 대사는 `[승인 대사 대기]`.
3. 이어하기 카드: 진행 여행이 있을 때만. 다음 장소 이름을 보여 줍니다.
4. 오늘의 길 확인 버튼: S-14로 갑니다.
5. 코스 카드: 이름, 소요 시간, 실내·야외 아이콘 (D-04 첫 코스에 따라 내용 변경).
6. 하단 탭 3개와 장부 진입.

**쓰지 않음**: 호감도 수치·게이지, 포인트·재화, 랭킹, 칸 채우기 독촉 문구, 정령·도사 수 언급 (worldview.md 2-1절, 3-3절, 4-10절).

## 4. 상태 (목업의 상태 선택 8종)

| 상태 | 장면·배지 | 주 버튼 | 추천 길 영역 |
|---|---|---|---|
| 진행 여행 없음 | 인사, 맑음 배지 | 오늘의 길 확인 | 카드 1~3개 |
| 진행 여행 있음 | 출발 준비 | 이어하기 | 카드. 누르면 경고창("진행 중인 여행이 있어요") 뒤에 새로 시작 |
| 진행 여행 + 경로 변경 알림 | 장면 아래 배너 "경로가 바뀌었어요" | 이어하기 | 카드 (F-21 알림 후 S-07) |
| 폭염 | 배지 빨강, 야외 중단 배너 | 가까운 쉼터 보기 | 실내·열차 위주만 |
| 호우·이동 보류 | 신규 이동 보류 배너 | 가까운 쉼터 보기 | 카드 없음, 안내 문구 |
| 날씨 확인 불가 | 배지 회색 "불러오지 못했어요" | 가까운 쉼터 보기 | 카드 없음. AI 추측 없이 쉼터만 (명세 496) |
| 중구 밖 (MVP는 중구만) | 배너 "지금 계신 곳은 중구가 아니에요" | 중구 코스 둘러보기 | 중구 코스 카드 |
| 코스 없음 | 갸웃 | 오늘의 길 확인 | 빈 상태 문구 |

- 표정과 대사는 승인 전이라 자리만 둡니다 `[승인 대사 대기]`.

## 5. 외출 전환 (코스를 선택하면)

- 흐름: 코스 카드 탭 → 하랑이가 문 쪽으로 걷고 문이 열려 골목이 보임 (약 1.5초, 건너뛰기 가능) → S-04 코스 상세.
- 여행이 진행 상태가 되는 시점은 S-04에서 "길 확인"을 누를 때입니다 (storyboard/app_screen_storyboard_v1.md S-04, S-05). 카드를 눌렀다고 바로 여행이 시작되지는 않습니다 `[결정 필요]`.
  - 후보 1 (제안): 위 흐름대로 연출만 시작, 여행 시작은 S-04에서.
  - 후보 2: 연출을 "길 확인" 순간으로 옮김. 이용자가 정보를 보고 정한 뒤 나서므로 결정이 앞서지 않습니다. 대신 코스 선택의 즉시성은 약해집니다.
- 필요한 그림: 문 닫힌 방 / 문 열림 / 문 밖 골목. 하랑이 걷는 스프라이트 `[확인 필요: 기존 파일에 있는지]`.
- 모션 줄이기 설정에서는 연출 없이 바로 전환합니다.

## 6. 배경 변형 (날씨와 시간대)

- 방, 가구, 구도는 고정하고 **창 밖, 하늘, 빛의 색, 바닥 빛무늬, 작은 소품**만 바꿉니다.
  - 왜 굳이: 변형마다 방이 달라지면 같은 곳이라는 느낌이 깨집니다. GPT에 기본본을 첨부해 "이 방은 그대로, 창 밖만 바꿔"로 만듭니다.
- 날씨는 모드 시나리오 5가지를 따릅니다 (plan/spec/treagent_tech_spec_v1.md:506-512). 모드표 통합은 `[결정 D-06]` 이후 맞춥니다.

| 날씨 시나리오 | 장면 변화 (창작) |
|---|---|
| 평상시·야외 (기본) | 맑은 하늘, 바닥에 창 모양 햇빛 |
| 더운 날·그늘 | 강한 햇빛, 창에 발 반쯤, 선풍기 |
| 폭염·실내 | 하늘이 뿌옇고 더 밝음, 커튼 닫힘, 선풍기 켜짐, 물 컵 |
| 약한 비 | 회청색 하늘, 창에 빗방울, 우산꽂이 |
| 호우·이동 보류 | 짙은 구름과 굵은 비, 방 안은 아늑한 등불. 번개와 공포 연출은 쓰지 않음 (CLAUDE.md) |

- 시간대: 아침, 낮(기본), 저녁, 밤 (창작 후보 2개: 3구분 아침·낮·저녁밤 / 4구분). 경계 시각은 `[결정 필요]`.
- 만드는 순서: ① 평상시·낮 ② 날씨 4종(낮) ③ 시간대 3종(맑음). 조합 전부(5 x 4)는 만들지 않고, 필요한 조합만 나중에 추가합니다 `[결정 필요]`.
